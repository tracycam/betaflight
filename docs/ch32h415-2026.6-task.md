## 基线

- 基线提交：`0db9244664892760da5823baa987faf7e1fac8bf`

- 参考实现：`~/BF_H417` 与上游未合并 PR #15364

## 目标

在 2026.6 维护版代码结构上完成 CH32H415 支持，生成可构建的 Betaflight 固件，并适配指定 Bootloader 和 TheiaOSD。

## 范围

1. 引入 CH32H41x SDK、CherryUSB 和 WCH RISC-V 工具链配置。
2. 接入维护版 `PLATFORM_SDK`、SDK hydration、工具链安装及 CI 分类机制。
3. 移植启动、时钟、链接、PFIC 中断、系统时基、RCC、GPIO/EXTI、DMA、SPI、UART、VCP、配置 Flash、ADC、PWM/DShot。
4. 按维护版接口适配公共驱动，避免影响现有平台。
5. 提供通用 `CH32H415` target，构建命令为 `make CH32H415 -j128`。
6. 链接布局遵守 `~/H415_FC_Bootloader` 的应用入口、Flash、配置区、SRAM 和共享内存约束。
7. 新增独立 TheiaOSD DisplayPort 驱动，包含画面、字库、应答和共享内存环形队列。
8. TheiaOSD ABI 的地址、版本、邮箱偏移和消息布局只存在于该驱动模块内，不散落到 MSP、串口、CRSF 或通用 OSD 代码。
9. 选择性吸收 BF_H417 的通用 USB、DMA、DShot 和串口修复。

## 不在本轮范围

- 独立 CH32H417 target。
- 修改通用 MSP、CRSF 或串口协议以承载 TheiaOSD ABI。
- 引入未经确认的其他板级外设配置；Bootloader/TheiaOSD 已明确占用的引脚、定时器和 DMA 除外。
- 未经确认的提交、推送或硬件烧写。

## 验证结果

- `make CH32H415 -j128`：通过，生成 2026.6.3 ELF/HEX。
- `make TARGET=CH32H415 binary -j128`：通过，生成 BIN。
- `make EXTRA_FLAGS=-Werror checks`：通过。
- `make EXTRA_FLAGS=-Werror test-all`：通过。
- `make SPEEDYBEEF405WING -j128`：使用 ARM GCC 13.3.1，通过。
- Theia producer host test：通过画面原子发布、背压、重同步、字体完成、重试和序列回绕测试。
- `check_image.py`：入口为 `0x08016000`，所有加载段均位于 Bootloader 允许的 Flash/SRAM 区域。
- `targets-ci-grouped-print`：CH32H415 正确归入 `ch32_sdk`。

## 待硬件验证与风险

- 未烧写硬件；Bootloader 跳转、BOOT0 DFU、VCP/MSP、配置保存、陀螺仪、8 kHz 调度、DShot 和 TheiaOSD 实际显示仍需实测。
- PFIC 临界区、SysTick/mcycle 时基和 DMA 时序不能由主机测试或编译结果证明正确。
- Theia 字体写入使用驱动内部最长 1 秒的同步等待，适配维护版现有 MSP ACK 语义；未引入 MSP/CRSF 异步改造。
- 正式上游提交前仍需确认 WCH SDK 的来源、版本和再分发许可，并保留 CherryUSB Apache-2.0 许可。

- 链接地址与 Bootloader 一致，无 Flash/SRAM 越界。
- TheiaOSD ABI 不出现在独立驱动之外。
- 自动检查和可行的构建回归通过。
