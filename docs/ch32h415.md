# CH32H415 platform notes

## Build

Install the WCH RISC-V toolchain and build the generic MCU target:

```sh
make SDK=ch32_sdk platform-tools-install -j128
make EXTRA_FLAGS=-Werror CH32H415 -j128
make EXTRA_FLAGS=-Werror TARGET=CH32H415 binary -j128
```

The target is registered as `ch32_sdk` in the CI target matrix. The compiler must support the `_xw` RISC-V extension used by WCH fast interrupts.

## Bootloader memory layout

The application layout matches the H415 bootloader contract:

- Bootloader: `0x08000000..0x08006000`
- TheiaOSD image: `0x08006000..0x0800E000`
- Font storage: `0x0800E000..0x08016000`
- V5F application: `0x08016000..0x080F0000`
- Betaflight configuration: `0x08018000`, 16 KiB
- FC SRAM starts at `0x20126000`, above the bootloader and inter-core shared areas.

`src/test/theia/check_image.py` verifies the entry point and every ELF load segment against the generated BIN. The checks do not verify electrical or runtime behavior.

## TheiaOSD boundary

`USE_THEIA_OSD` selects the isolated Theia DisplayPort driver. Its shared-memory ABI v4 is private to `src/main/io/displayport_theia*`; generic MSP, CRSF and serial protocols do not carry that ABI.

The driver implements complete-screen transactions, backpressure and resync handling, font completion and bounded waits. Font writes are rejected while armed. Bootloader/Theia-owned GPIO, timers and DMA requests must not be reassigned.

## Verification

```sh
make EXTRA_FLAGS=-Werror checks
make EXTRA_FLAGS=-Werror test-all
make EXTRA_FLAGS=-Werror SPEEDYBEEF405WING -j128
```

Also run the Theia producer test and the image checker after changing the driver or linker layout.

## Validation limits

Compilation and host tests do not establish flight safety. PFIC interrupt masking, DMA ordering, UART/USB/DShot timing, flash power loss, bootloader/DFU transitions and actual TheiaOSD output require target-board validation. WCH SDK redistribution terms and maintainer acceptance must be resolved before an upstream submission.
